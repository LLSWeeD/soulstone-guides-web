# Soulstone guides: web/mod project notes

Дата старта: 2026-10-05. Цель: сделать гайды по Soulstone Survivors не как навык, а как веб-интерфейс и/или мод. Пока для личного использования.

## Решения
- Формат: гибрид. Единый источник данных (JSON) -> статический сайт (GitHub Pages) -> позже мод-оверлей (MelonLoader, на базе SoulstoneTweaks-Melon).
- Порядок: 1) схема JSON + валидатор, 2) сайт, 3) ТЗ для исполнителя-ИИ, 4) прототип разведки для мода (прочитать карточки выбора в логе).
- Навык soulstone-build-guide превращается в генератор данных (JSON), а не в конечный продукт.

## Смена плана (2026-10-06)
- Мод отменён. Делаем только веб-интерфейс (статический сайт), который потом разворачивается из git (GitHub Pages).
- Остаётся: JSON-схема + валидатор -> сайт -> ТЗ для ИИ-исполнителя, пополняющего данные.
- Пункты про мод-оверлей и разведку карточек в игре выше больше не актуальны.

## Масштаб
- 23 персонажа x 4 оружия = 92 пары.
- Наивный прогон: ~100-300k токенов на пару => ~9-28M (оценка, не измерение).
- Экономия: слои (общий справочник x1, персонаж x23, оружие x92 коротких) => ~3-8M. Кэш сырых источников, обновление только по патчам, дешёвая модель для сбора.
- Сначала пилот на 2-3 персонажах (8-12 пар), замерить реальную стоимость.

## Пилот (2026-10-06) — результаты
Три агента (Sonnet), по одному на персонажа, параллельно. Карточки: data/characters/{Sentinel,Barbarian,Samurai}.json, все проходят validate.py (по 1 ожидаемому warning: нет legacy_check).
- Расход субагентов: Samurai 68,6k, Sentinel 83,5k, Barbarian 83,1k = ~235k токенов (бюджет 300k). Большая часть фиксированная (TZ, схема, пример ~15-60k на агента), поэтому на полную базу ~20 карточек выходит ~1,2-1,8 млн, а не 0,5-1 млн, как оценивалось. Снижается сжатым промптом.
- Проверка мной по исходникам: Sentinel и Barbarian совпадают с гайдом (навыки, руны, пассивки, оружие). Samurai: агент пропустил расхождение гайда с вики (Shadow Slice vs руна Swift Execution) — исправил вручную, claims получили статусы conflict/verified. Вывод: сверку claims с вики агенты не делают, это отдельный шаг (Opus/высокий effort).
- Проблема схемы: пассивку, которой нет в справочнике (Hemorrhage, Skill Chain, Battle Stance, Shredding Armor, War Experience и др.), нельзя записать, агенты их выкидывали, хотя для билдов это ключевые пассивки. Решение: добавить в passives необязательное поле `power_name` + расширить справочник пассивок (парсер таблиц Powers неполный).
- Мелочи: game_version верхнего уровня = версия, к которой приведена карточка (1.5d); флаг «нет актуального гайда» не нужен, сайт выводит его из отсутствия guides[kind=current]; архетипы и роли навыков агенты ставят по своей оценке (в гайдах их нет).
- Руны legacy-гайда без разделения Tenacity/Versatility агенты кладут в tenacity; нормально.
- Следующие шаги: (1) power_name в схеме + доработка парсера powers [Sonnet]; (2) legacy_check, проверка claims по вики, derived для 3 карточек [Opus/high effort]; (3) прототип сайта на 3 карточках [Sonnet]; (4) массовое извлечение остальных 20.
