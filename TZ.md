# ТЗ: база данных и сайт гайдов Soulstone Survivors

Версия 0.2, 2026-10-06. Статус: **утверждено пользователем** (EN желателен, бюджет пилота 300 тыс. ок).
Изменения против 0.1: отказ от гайдов «персонаж + оружие», вместо них карточка персонажа; найдены структурированные данные вики (Lua-модули); пилот: Sentinel, Samurai, Barbarian.

## 1. Цель
Статический сайт с гайдами по Soulstone Survivors. Собирается из JSON-данных, разворачивается из git (GitHub Pages). Личное использование, языки RU/EN. Актуальная версия игры: **1.5d** (12.06.2026).

## 2. Концепция
- **Карточка персонажа** (23 шт.). Внутри: факты из вики (статы, 5 оружий R1–R5, навыки, руны, вознесение), актуальные гайды, старые гайды как дополнительная информация.
- **Общий гайд по игре** (1 страница): билды по механикам, источник lb-product.
- **Справочник**: навыки, пассивки (Powers), руны, оружие, RU/EN.
- Билд принадлежит гайду, а не оружию. Если гайд называет оружие, оно указывается в билде; если нет, поле пустое. Гайды покрывают оружие неравномерно, и это нормально.

### Известные пробелы вики
- Таблица на странице `Weapons` неполная (R1–R4, 12 персонажей). Брать оружие со страниц персонажей (`weapon card`).
- У Samurai на вики только 4 оружия (R1–R4), легендарного нет. В выжимке сказано, что легендарное у Samurai появилось в 1.5.
- Руны-семейства «Skill Mastery: X», «Skill Inclination: X», «Skill Affinity: X» открываются достижениями и отсутствуют в `Runes/Data`. Собирать из достижений (`{{ac|...|rune|...}}`) на страницах персонажей.
- Раздел `Builds` на страницах персонажей пустой.
- Карточка оружия Blacksmith имеет другой формат, проверить в парсере.

## 4. Конвейер

| Шаг | Кто | Что |
|---|---|---|
| 1. Fetch | код, `scripts/fetch_all.py` | **Сделано.** raw/: вики (419 страниц с модулями), 19 гайдов, 3 страницы |
| 2. Clean | код, `scripts/clean.py` | **Сделано.** clean/: текст по заголовкам, raw не трогается |
| 3. Reference | код, `scripts/build_reference.py` | Модули и шаблоны вики в `data/reference/*.json` + RU из глоссария |
| 4. Extract | ИИ, по одному персонажу на агента | Только раздел `Example Builds` гайда (обзор персонажа повторяет вики, его не читаем). Выход: карточка по схеме |
| 5. Validate | код, `scripts/validate.py` | Схема + все id есть в справочнике + обязательные поля |
| 6. Derive | ИИ, высокий effort | Блок `derived` (приоритет банов, правила при повышении уровня) и `legacy_check` для старых билдов |
| 7. Build | код | Сайт из JSON |

## 6. Данные

### 6.1 Справочник (`data/reference/`, генерируется кодом)
- id: ключи модулей вики (`RainofArrows`, `WeaponExpert`); для персонажей и оружия: имя без пробелов и знаков (`Sentinel`, `HuntressBow`).
- У каждой записи: `id`, `name_en`, `name_ru` (из глоссария, может быть пусто), данные из вики, `wiki_url`.
- Персонаж: класс, статы, типы навыков, условие открытия, 5 оружий, руны дерева навыков, вознесение, достижения.
- Оружие: редкость R1–R5, тип, статы, два навыка, Artifact Power.

### 6.2 Карточка (`data/characters/<Id>.json`)
Схема: `schema/character-card.schema.json`. Пример с одним реальным билдом: `schema/example-Sentinel.json`.
- В карточке только то, чего нет в справочнике: `summary`, `guides[]`, `derived`, `gaps`.
- `guides[]`: `kind` = `current` или `legacy`, версия, дата, ссылка, `builds[]`.
- Билд: `weapon_id` (может быть null), `archetypes` (stack, multiplier, dot, summon, generalist, synchrony из выжимки), `core_mechanics`, `skills[]` с ролью, `passives[]` (пассивка `power_id`, семейство пассивок `power_id` + `variant` вида «Тип -> Тип» для Skill Chain, `power_name` для пассивок, которых нет на вики, или стат `stat`; + приоритет), `runes` (4 Tenacity + 3 Versatility, руна-семейство как `id` + `variant`), `titan_powers`, `playstyle`, `claims[]` (числа на проверку), `legacy_check[]` (только для старых), `confidence`.
- `derived`: то, чего в источниках нет (баны, правила при повышении уровня). На сайте помечается «вывод, не из источника».
- Тексты: `{ru, en}`, `ru` обязателен, `en` желателен.

## 7. Сайт
- Главная: 23 персонажа, фильтры (класс, типы навыков), поиск. Отметка «нет актуального гайда».
- Карточка персонажа: факты из вики → актуальные билды (вкладки) → старые гайды (свёрнуто, с плашкой «патч 1.2» и `legacy_check`) → выводы (`derived`) → источники.
- Общий гайд по механикам.
- Справочник: навыки, пассивки, руны, глоссарий RU/EN.
- Переключатель RU/EN, тёмная тема, адаптив под телефон.
- Генератор: `scripts/build_site.py` (чистый Python, без Node): data/ -> dist/ (статические HTML + site/style.css + site/app.js). Деплой: GitHub Actions -> Pages (собрать dist/ и опубликовать).

## 8. Требования к исполнителю шага 4
- Только валидный JSON по схеме.
- Только id из справочника. Не нашёл соответствие — запись в `gaps` и `confidence: low`, ничего не выдумывать.
- Пассивку, которой нет в справочнике, не выкидывать: писать `power_name` (английское название как в гайде). Валидатор даст предупреждение, это нормально.
- Пересказывать, не копировать. Ссылка на источник в каждом гайде.
- Утверждения с числами — в `claims` со статусом `unverified`, проверка по вики отдельным шагом.
- `validate.py` должен проходить без ошибок.

## 9. Пилот
- **Персонажи:** Sentinel (свежий гайд 1.5d, 28.08.2026), Barbarian (гайд 1.5d, 12.06.2026, в тексте есть упоминание 1.1), Samurai (гайда нет, на вики 4 оружия из 5).
- Что проверяем: справочник собирается; извлечение даёт валидную карточку; качество текста; поведение карточки без гайда; работа с Steam-1.2 и `legacy_check`; реальный расход токенов.
- Бюджет пилота: до 300 тыс. токенов (оценка: 3 персонажа × ~10 тыс. на чтение + вывод + проверка). Остановка и отчёт при превышении.
- Приёмка: `validate.py` без ошибок; у каждого билда есть источник; пользователь проверил смысл хотя бы по одному персонажу.
- Оценка полной базы (23 карточки): примерно 0,5–1 млн токенов. Уточнить после пилота.
